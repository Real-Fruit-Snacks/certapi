Send requests with the client certificate already in your Windows store

Some internal APIs don't take a password; they ask for a certificate. certapi picks yours from CurrentUser\My or LocalMachine\My and lets Windows sign the TLS handshake, so the private key never leaves the store and never has to be exportable. A .pfx or .pem file works too.

Install in PowerShell. No installer, no admin rights.

PowerShell 
mkdir "$env:LOCALAPPDATA\certapi" -Force; cd "$env:LOCALAPPDATA\certapi"curl.exe -LO https://github.com/Real-Fruit-Snacks/certapi/releases/latest/download/certapi.execurl.exe -LO https://github.com/Real-Fruit-Snacks/certapi/releases/latest/download/ApiTester.App.exe

certapi.exe is the command line and ApiTester.App.exe the desktop app, both from the latest release with the .NET runtime inside. Add the folder to your PATH; certapi update later replaces both, each checked against the SHA-256 GitHub publishes. With Scoop: scoop install https://github.com/Real-Fruit-Snacks/certapi/releases/latest/download/certapi.json

Some endpoints don't take a password

They ask the browser to choose a certificate and complete a mutual-TLS handshake. Most API clients want that certificate and its private key as files on disk, which enterprise and smart-card certificates deliberately don't allow. certapi uses the certificate where it already is, and the operating system does the signing.

The certificate is optional. With none selected certapi is an ordinary HTTP client, so the same collections, environments and assertions work against anything else too. I wrote it for my own internal APIs; it assumes Windows 10 or 11 and nothing else.

Which certificate does this server want?

certapi doctor connects one stage at a time and names the stage that broke. At the TLS stage it reads the authorities the server will accept client certificates from, and checks them against every certificate in your store. This is the run the seal draws, exactly as certapi printed it.

All stages passed in 643 ms.
  1. The certificate certapi sent. Here it came from BadSSL's test file; with --cert "CN=…" it is one from your store, and Windows signs with its key.
  2. Read from the server's certificate request during the handshake: the issuers it will take a client certificate from.

Without --cert-file, the same run reads client certificate presented: none and ends with HTTP/1.1 400 Bad Request. Run 5 November 2026 with certapi 1.96.1 on Windows 11.

certapi on the command line

The status line goes to stderr and the body to stdout, so a script can pipe one and read the other. Exit codes: 0 success, 1 failure, 2 usage, 3 data.

PS> certapi send https://client.badssl.com/
400 Bad Request · 262 B · 680 ms · TLS 1.2
<title>400 No required SSL certificate was sent</title> …

PS> certapi send https://client.badssl.com/ --cert-file badssl.com-client.p12 --cert-password badssl.com
200 OK · 687 B · 777 ms · TLS 1.2 · client cert presented

Both against BadSSL's public test server, the body cut to its title.

# one request, certificate from the store
certapi send https://internal.corp/api/orders --cert "CN=matt"
# log in, capture the token, reuse it
certapi send https://internal.corp/auth --capture token=access_token --workspace team.json
# a collection as a pass/fail suite (exit 1 on any failure)
certapi run "internal api" --env Prod --json
# the bytes, as framed and as received
certapi send https://internal.corp/api/orders --wire
# gRPC behind mutual TLS
certapi grpc call api.internal:5001 my.pkg.Greeter/SayHello -d '{"name":"Ada"}'
# stream, bench, mock, MCP
certapi sse https://internal.corp/events --max-events 5
certapi bench https://api.internal/health -n 500 -c 20
certapi mock --har session.har --port 8770
certapi mcp --cert "CN=matt" --allow internal.corp

Hosts here are examples. certapi <command> --help lists every flag, curl habits like -k, -i and send -d @file work, and a mistyped flag names the one you meant. The CLI reference has them on one page.

For an app that can't present a certificate

certapi serve is a local gateway that adds your certificate on the way out. Point the app at the port. It fronts one site or many: named sites, a certificate and settings per site, one origin each with --vhost, logins across hosts with --browser, a whole gateway kept in a profile. --check prints the table without binding anything. Requests to hosts you didn't allow are refused.

PS> certapi serve --port 8819 --cert-file badssl.com-client.p12 --cert-password badssl.com --upstream badssl=https://client.badssl.com

One engine, two front ends

The desktop app and certapi share one engine, one request model and one workspace on disk, so a request built in the window runs from a script.

Certificates and networks
The Windows certificate store (your Personal store or the machine's), picked by subject, issuer or serial, or a .pfx/.pem file; a smart-card PIN supplied ahead for headless jobs. Server pins by leaf, issuer or key; a private root from a file with --ca-file; revocation checking. System proxy, PAC, SOCKS, bypass lists, --offline.
Requests
Tabs, collections, environments with {{variables}}, response captures, request chains, assertions, data-driven runs from CSV/JSON, response diffing against a baseline. Import cURL, Postman, OpenAPI, HAR; export OpenAPI, HAR, markdown notes.
Diagnostics
doctor connects one stage at a time and names the one that broke, including the CAs the server accepts client certificates from, matched against yours. --trace, --wire and --frames show what the stack did, down to the plaintext bytes. No driver, no admin.
Gateway and mock
serve adds your certificate for apps that can't. mock is a standing test server over HTTP, HTTPS or mTLS, or a replay of a captured HAR.
Auth
Bearer, Basic, OAuth 2.0 (client credentials, password, refresh, auth-code with PKCE, device code), Windows Integrated (Kerberos/NTLM), browser session capture, and automatic token reuse per host. Secrets are DPAPI-encrypted at rest.
Automation
run turns a collection into a pass/fail suite with exit codes for CI. bench reports p50/p90/p99 latency over a pooled connection. grpc calls services via reflection or a descriptor set. mcp exposes all of it to an AI agent behind a host allowlist.

The desktop app

Tested on

  • Windows 11 23H2 · .NET 9 SDK 9.0.320 or later
  • Windows Server 2022 · headless certapi only
  • GitHub Actions windows-latest on every push: build with warnings as errors, then the test suite
  • Not tested: Windows 10 before 22H2, ARM64 Windows. Probably works, no promises.

Known issues

  • The Rendered view needs the Edge WebView2 runtime. Windows 11 ships it; without it that tab says so and the rest works.
  • certapi serve does not proxy gRPC.
  • --protoset needs a descriptor set you already have; certapi does not compile .proto files.
  • --http3 is Windows 11 / Server 2022 and direct connections only.
  • Through a proxy, TLS version, cipher and certificate-presented details are not visible; --no-proxy brings them back.
  • Over the plaintext gateway, __Host-/__Secure- cookies cannot work; serve --tls is the fix.
  • serve --rewrite-body reaches URLs written into a page, not ones a script assembles at run time; --vhost needs no rewriting at all.
  • A proxy that itself requires a client certificate is not supported.
  • --pac and --cert-pin are Windows-only; --sni works on direct connections only.
